# Scan-time campaign and location groups (#444, #389)

The single-code analytics result optionally returns `attribution:{byCampaign,byLocation}`. Each bucket has `{key,openings,probableScans,excludedOpenings}`. These groups use accepted retained **event snapshots**, not the current code catalog. Each dimension sums to the same loaded sample's totals, including excluded bot/prefetch openings. No conversion, person, revenue or cross-code aggregation is inferred.

Campaign keys are trimmed strings up to 160 characters without controls. Missing/empty/malformed legacy campaign values use the reserved empty key and display **Ukendt kampagne**, without dropping an otherwise valid event or inventing its historic campaign. Valid native location IDs remain IDs; explicit null uses empty key and **Uden registreret afdeling**. Existing malformed-location/brand/code rejection is preserved. Historical IDs never resolve through another brand, and no lookup invents a retired location's current name.

Existing scoped query, current-location restriction for delegated users, brand-wide historical location access, timestamp/expiry retention clamp, stable order, sample cap and incomplete flags apply **before** grouping. Invalid/expired/out-of-scope rows never enter either dimension. CSV adds `campaign_at_scan` and `location_at_scan` aggregate rows with the same complete/period/timezone/scope metadata. Missing optional attribution remains absent rather than synthesized from current catalog labels.

The client accepts optional `attribution` from the same server report as its metrics. Root's workspace adapter passes `report?.attribution`. The separate tables **Kampagner ved scanning** and **Afdelinger ved scanning** explicitly describe historical event snapshots for the selected code/loaded period and display location IDs. Current catalog campaign/placement selectors and columns retain their earlier metadata disclaimer; they are not substituted for historical groups.

Service regressions cover changed campaign/location snapshots, excluded openings, unknown legacy campaigns, bounds/retention/scope filtering and aggregate CSV. Actual component browser checks cover historical labels, unknown/retired IDs, no current-catalog substitution, absent optional data and mobile layout.
