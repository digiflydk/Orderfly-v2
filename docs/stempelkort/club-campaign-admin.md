# Club campaign administration (#469 / #459)

Loyalitet → Club & nyhedsbrev is the single place for a merchant's signup **campaign** (`loyaltyCampaigns/{brandId}`): the checkout offer (none, newsletter or Club) plus welcome and profile stamps. The stamp card (`loyaltyPrograms`), members, stamps and consents are not part of the campaign and are never changed here. Promotion → Discounts only links here. Loading a page does not write configuration or activate a campaign.

## Campaign overview (`/superadmin/loyalty/club`, #852)

One table, one shared header row, one row per brand where the administrator holds `orderfly.stamp_cards:settings`, `orderfly.discounts:view` or `orderfly.discounts:edit` for the whole brand:

- **Dato**: the current campaign's creation date: the first saved non-empty version in `loyaltyCampaignAudit` after the latest empty one (no checkout offer and both bonuses off, which is what delete writes). A deleted campaign therefore shows "—", and setting it up again starts a new date (`campaignStartedAt`).
- **Merchant**: brand name, linking to the merchant page.
- **Type**: Club, Nyhedsbrev, "Nyhedsbrev (standard)" when no campaign is saved (checkout's legacy default), or —. Uses `checkoutSignupMode`, the same rule as checkout.
- **Rabat**: the signup discount checkout actually offers for the type (for example "Procent · 15 %"), — when none, "Ingen adgang" without `orderfly.discounts:view`.
- **Status**: Live when customers see the signup in checkout: newsletter mode (also while the newsletter service is pending; checkout then explains the delay), or Club mode that checkout does not suppress (programme missing or inactive, texts not ready, or no usable brand slug, matching `getCheckoutSignupAction`). Otherwise Ikke live.
- **Omnisend**: Aktiv/Ikke aktiv, column shown to platform superusers only.
- **Handlinger**: icon controls Vis, Rediger and Slet with tooltips and accessible names. Rediger and Slet require both campaign permissions.

Search and the Alle / Live / Ikke live filters work in the browser. "Ny kampagne" lists editable brands without a saved campaign.

**Slet** opens a confirmation dialog stating what is kept (members and stamp cards, newsletter consents, discounts already granted). Confirming calls `deleteClubCampaign`, which saves the campaign as `checkoutMode: 'none'` with default (disabled) stamps through `saveClubCampaign`: the same permissions, expected version and audit apply. The document is kept, because a missing document means the legacy newsletter checkout. A deleted campaign starts over when created again; the audit keeps its history. Signup discounts in Promotion → Discounts are not deleted.

## Merchant page (`/superadmin/loyalty/club/{brandId}`)

A header with status, creation date and a merchant switch; plain-language warnings (unreadable campaign, Club not shown in checkout, Club offered without a signup discount); and a step guide with status: 1 Stempelkort, 2 Club-tekster, 3 Tilbud i checkout, 4 Tilmeldingsrabat, 5 Stempler, 6 Omnisend (superusers only). A step without the needed full-brand permission states what is missing, for example "Kræver: Rediger rabatter". Step 3 uses three radio cards with a "Sådan ser kunden det" preview; step 5 edits welcome and profile stamps. Steps 3 and 5 are saved together with one Gem ændringer; Annullér ændringer reloads the saved campaign. A brand outside the administrator's grants returns not found. Every card and action rechecks its grants server-side (`src/lib/loyalty/stamp-card/club-admin-summary.ts`).

The checkout selector stores exactly one mode: none, newsletter or Club. The percentage discount is still configured using the existing Promotion discount form. Welcome and profile bonuses each have their own enabled flag, stamp count and optional start/end time. Profile bonus criteria select one or more of phone, birth date and gender; “prefer not to say” is a valid gender answer. All campaign times use Europe/Copenhagen, regardless of the administrator browser's timezone, and are stored as epoch milliseconds. Nonexistent Danish wall-clock times during the spring DST gap fail validation instead of shifting silently.

An absent campaign document preserves the pre-existing newsletter checkout behavior and leaves bonus stamps disabled. An existing malformed or foreign document fails closed and cannot be silently overwritten by a default configuration. A saved `none` explicitly disables the checkout signup offer.

Both full-brand `orderfly.discounts:edit` and `orderfly.stamp_cards:settings` permissions are required to load or save this combined panel. A location-only grant or a grant to another company is insufficient. Save validates the configuration and expected version, then rechecks both permissions in the same transaction as the configuration write. A concurrent edit returns `campaign_changed`; the user can explicitly reload rather than silently losing changes. The config-only audit stores the brand, actor principal hash, time, version and enabled flags, without customer profile details.
