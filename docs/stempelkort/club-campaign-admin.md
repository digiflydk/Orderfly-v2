# Club campaign administration (#469 / #459)

Loyalitet → Club & nyhedsbrev (`/superadmin/loyalty/club`, #850) is the single place for Club and newsletter signup. It replaced the panel previously at the top of Promotion → Discounts, which now only links here. Loading the page does not write configuration or activate a campaign.

The page preselects the first brand the administrator may administer and offers a brand switch when there are several. A read-only status overview shows, per card and only when the administrator holds that card's full-brand permission:

- Checkout offer (none, newsletter or Club), including the legacy newsletter default when no campaign is saved and a warning when the saved document is unreadable. A saved Club mode is flagged as not shown when checkout suppresses it (programme missing or inactive, texts not ready, or the brand has no usable slug), matching `getCheckoutSignupAction`. Requires `orderfly.discounts:edit` and `orderfly.stamp_cards:settings`.
- Active, unassigned newsletter and Club signup discounts, or "Ingen aktiv rabat", each marked "Bruges i checkout" or why not (checkout mode, suppressed Club offer, or newsletter service not yet set up), using the same mode rule as checkout. Requires `orderfly.discounts:view`; each discount permission is evaluated on its own. The link to create a signup discount requires `orderfly.discounts:create`.
- Welcome and profile stamps: enabled, granted now (period, stamps and an active programme with ready texts), stamps and period. Same permissions as the checkout offer.
- Club texts: programme created/active and whether every placeholder can be filled, with a link to the stamp-card settings. Requires `orderfly.stamp_cards:settings`.
- Omnisend: connected, disabled, not configured or invalid mapping, with a link to Newsletter & Omnisend. Shown to platform superusers only; no keys, contacts or provider IDs are returned.

A card without the permission states what is missing, for example "Kræver: Rediger rabatter". The menu entry is shown with `orderfly.stamp_cards:settings`, `orderfly.discounts:view` or `orderfly.discounts:edit`; every card and the save action recheck their own grants server-side (`src/lib/loyalty/stamp-card/club-admin-summary.ts`). Below the overview the campaign panel edits the selected brand; select the brand and explicitly save the settings.

The checkout selector stores exactly one mode: none, newsletter or Club. The percentage discount is still configured using the existing Promotion discount form. Welcome and profile bonuses each have their own enabled flag, stamp count and optional start/end time. Profile bonus criteria select one or more of phone, birth date and gender; “prefer not to say” is a valid gender answer. All campaign times use Europe/Copenhagen, regardless of the administrator browser's timezone, and are stored as epoch milliseconds. Nonexistent Danish wall-clock times during the spring DST gap fail validation instead of shifting silently.

An absent campaign document preserves the pre-existing newsletter checkout behavior and leaves bonus stamps disabled. An existing malformed or foreign document fails closed and cannot be silently overwritten by a default configuration. A saved `none` explicitly disables the checkout signup offer.

Both full-brand `orderfly.discounts:edit` and `orderfly.stamp_cards:settings` permissions are required to load or save this combined panel. A location-only grant or a grant to another company is insufficient. Save validates the configuration and expected version, then rechecks both permissions in the same transaction as the configuration write. A concurrent edit returns `campaign_changed`; the user can explicitly reload rather than silently losing changes. The config-only audit stores the brand, actor principal hash, time, version and enabled flags, without customer profile details.

Validation: `node --test tests/unit/loyalty-club-admin-summary.cjs` covers per-card permissions, foreign/location denials, the legacy default, corrupt campaigns, signup discount selection and superuser-only Omnisend status; `CART_CHROMIUM_PATH=... node --test tests/unit/loyalty-club-admin-browser.cjs` renders the overview and fixed-brand panel at 390 and 1440 px, including missing permissions. `node --test tests/unit/loyalty-campaign-admin.cjs` covers authorization, concurrent changes, revocation, legacy defaults and corrupt configuration. `CART_CHROMIUM_PATH=... node --test tests/unit/loyalty-campaign-admin-browser.cjs` renders the actual panel against synthetic server-action responses for successful explicit saves, field validation, stale versions and access denial at mobile/desktop widths. These checks do not activate production campaigns. Deployment and controlled live acceptance remain coordinator gates.
