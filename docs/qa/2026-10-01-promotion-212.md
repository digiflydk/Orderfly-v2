# Promotion QA #212 — percentage limits, customer binding and empty tiers

Scope: only the three new findings in #212. This is not an A–Z approval and does not resolve #209, #193, #187 or #210.

## Causes and changes

1. Code/newsletter and upsell schemas accepted positive percentages without an upper bound. Both client and server now require a finite value greater than 0 and at most 100 for percentage discounts. Zero remains invalid, matching the existing positive-discount policy. Fixed amounts may exceed 100. Upsell input parsing rejects numeric prefixes followed by garbage; its form now actually runs its schema before dispatching the action, with inline and summary feedback. Standard discounts and tiers already capped percentages; their numeric validation now explicitly rejects non-finite values. Scratch-card percentage prizes already validate 0 < value <= 100 and were not changed or activated. Combos use fixed prices.
2. The customer selector offered no clear option. In addition, omitting the field caused the transaction merge to retain the previous customer ID. “Alle kunder” explicitly clears it; the action stores null. Customer ownership validation still runs when assigning an ID. Existing usage, order references, history, eligibility and activation are retained.
3. Empty tiers already failed shared server/client validation, but React Hook Form places array errors under `root.message`. `FormMessage` now reads that path. The standard-discount form also provides persistent submit failure feedback. A browser mutation check using the original FormMessage reproduces the missing inline error; the repaired component passes.

No changes to pricing algorithms, reservation lifecycles, paid revenue or authorization mappings.
